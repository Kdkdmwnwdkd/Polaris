## 1. 这一轮到底做了什么

一句话：**给「模型要执行工具」这件事装了一道能表态、能挂起、能超时的闸门，然后让桌宠成为第一个用户。**

在此之前，桌宠是 `Consent.Deny("桌宠气泡上没有审批按钮")`——整个工具表被锁在四个只读工具上，
用户说「帮我打开微信」，模型只能回「我这个界面没法确认」。现在有卡了。

### 1.1 四层结构（按依赖顺序读）

| 文件 | 干什么 | 为什么单独一层 |
|---|---|---|
| `core/src/main/java/com/beichen/polaris/core/Consent.kt` | 封闭契约：`Ask(handler)` / `Deny(reason)`，`decide()` 返回四种 `Decision`（Allowed / Denied / **Unavailable** / Failed） | 只依赖 Kotlin，能被所有模块引用；`null` 从类型里被消除 |
| `core/src/main/java/com/beichen/polaris/core/ApprovalGate.kt` | 挂起 / 超时（45 秒）/ 取消，四种 `Outcome`（ALLOWED / DENIED / TIMEOUT / CANCELLED） | 只依赖 coroutines，一个文件就能真编真跑 |
| `app/src/main/java/com/beichen/polaris/pet/PetApproval.kt` | 进程级审批状态 + 参数摘要 + 生命周期 | 要 `Context` / `StateFlow`，进不了 `:core` |
| `app/src/main/java/com/beichen/polaris/pet/ConfirmRequiredTool.kt` | 装饰器：给任意工具加「必须确认」，不改工具类 | 场景差异留在调用点 |
| `app/.../pet/PetPanel.kt` → `ApprovalCard` | 一张卡：工具名 + 一句参数 + 两个按钮 | 纯渲染，状态由宿主传 |

### 1.2 三个当时吵过的取舍（别推翻，除非想清楚）

1. **`cancelAll` 传 `Outcome` 而不是 `false`。** 最初用 `complete(false)` 解除等待，与「用户点拒绝」
   共用一个值。harness 的 B8 当天就抓到：界面销毁后等待方拿到 `DENIED`，工具结果写
   「用户拒绝了该操作」——而用户从头到尾没看见那张卡。**界面销毁不是用户拒绝。**
2. **没有「本次会话都允许」。** 那需要持久化策略表，现在没有。内存版的「本次允许」会被当成
   长期授权，用户下次点得更快。
3. **卡片出现时自动展开气泡。** 只订阅不展开，收起态下卡片不在组合里，模型停在 45 秒超时，
   用户眼前只有一个静静待着的悬浮球——**「声称有通道，实际没人看得见」**。

## 3. 没做的事，按怎么接手的顺序

### A. 真机手测（30 分钟，只有人能做）

装 release 包，按 `docs/qa/真机矩阵-v1.md` I 段做。三条通过标准：

| ID | 判据 | 漏了会怎样 |
|---|---|---|
| **I1** | 气泡**收起**状态下说「打开<已装应用>」→ 气泡自动展开，顶部出现「要执行 app_launch 吗？」+ 参数 + 两个按钮 | 卡画不出来 / 收不到触摸，用户永远等不到确认 |
| **I2** | 点「允许」→ 目标应用真被拉到前台 | 审批通过但没执行，等于白问 |
| **I3** | 卡片出现后**什么都不点**，等约 45 秒 → 卡片消失、气泡出现「需要用户确认」类结果；**随后再说一句话，仍然正常回答** | `ApprovalGate` 漏 `reopen()` → 桌宠从此不再问任何事，而界面上看起来一切正常 |

I3 后半句最容易漏，也最难在模拟器上发现：`cancelAll()` 之后 gate 是 `closed` 状态，
不 `reopen()` 的话下一次 `await()` 立刻返回 CANCELLED，所有工具调用瞬间失败。

另两条（顺路做）：**H5 锁屏拦截**（模拟器 `isKeyguardLocked` 恒 false）、
**P1–P3 容器**（需 arm64 真机，x86 模拟器上 musl 程序 `execve` 不了）。

## 4. 环境坑（每一条都真的吃掉过一小时）

### 4.1 沙箱（本机）

| 症状 | 真因 | 修法 |
|---|---|---|
| `curl`/`git` 报 `exit 60` 或 `SSL certificate problem` | `/etc/ssl/certs/ca-certificates.crt` 退化成 718 字节（重启回退） | `cp $(python3 -c "import certifi;print(certifi.where())") /etc/ssl/certs/ca-certificates.crt` |
| `ssh` 报 `No user exists for uid 0` | `/etc/passwd` 被清空 | 重建最小账户文件（`root:x:0:0:root:/root:/bin/bash`） |
| 84 个 runner 齐红，报编译器与 stdlib 版本不匹配 | Gradle 缓存里混进畸形目录 `h/`（含 2.2.21 编译器 jar），`find \| head -1` 优先命中它 | `mv ~/.gradle/caches/*/h /tmp/quarantine-*` 隔离，别删别的地儿 |
| 7 个老 harness 报「插件路径不存在」 | 沙箱缺 `/tmp/kotlinc` shim（CI 有，本机没有） | 复刻 CI 的 shim：`/tmp/kotlinc/bin/kotlinc` + `lib/kotlinx-serialization-compiler-plugin.jar`，harness 靠 `command -v` 定位 |

### 4.2 云服务器（instabox，`ssh -p 2222 ...@ssh.instabox.sh`）

- 已清理，`/data` 45%。**只剩 `~/android-sdk`（6.6G），是有意留的**——重装它才是下次验证的真正成本。
- 上次留了个坑：`--exclude=build` 传源码包会误伤 `core/.../core/build/`（那是源码包名不是构建产物），
  编译失败两次。打包时用 `--exclude='*/build/*'`。
- 模拟器 `-accel off` 纯软件跑（`/dev/kvm` 节点在但打不开），UI 频繁 ANR。所以**交互项一条都别在云上假装验**。
- 用完记得 `adb emu kill`——上次一个 `ui30` 挂了 20 小时没人管。

### 4.3 往 GitHub 推

不要走 OAuth 设备码流程（用户明确拒绝过）。直接 PAT：

```bash
git -c credential.helper= push "https://x-access-token:${TOKEN}@github.com/Kdkdmwnwdkd/Polaris.git" main:main
```

`-c credential.helper=` 是为了不把 token 落进 `.git/config`。
推完如果 `git status` 还显示 `ahead N`，别慌——是本地 `origin/main` 引用没刷新，
`git ls-remote` 或 `git fetch` 确认真实状态，别重复推。
