# 云端服务器模拟器验证报告（2026-11-14）

> 目标：用 InstaBox 云机器上的无头 Android 模拟器，把积压的 28 条真机判据（P11 10 + P12 9 + P13 9）尽可能先跑一遍。
> 结论先说：**能用，但只覆盖一半**——窗口 / 通知 / 服务生命周期这批能验，语音与 ROM 相关的一批还是得真机。

---

## 一、这台机器到底能跑什么

| 检测项 | 结果 | 含义 |
|---|---|---|
| `/dev/kvm` | 节点存在，但 `open()` 返回 `ENODEV` | **嵌套虚拟化不可用**，KVM 是摆设（和 10-22 那次结论一致） |
| `emulator -accel-check` | `Could not open /dev/kvm : No such device` | 只能 `-accel off` 走 QEMU TCG 软件模拟 |
| CPU / 内存 | 4 vCPU AMD EPYC / 7 GB | 够跑 1 台 2 GB 的模拟器 |
| 磁盘 | `/` 16 G（余 5.9 G）、`/data` 20 G（余 1.9 G） | **卡脖子**，见下 |
| 模拟器版本 | 37.2.13（这次新装的） | 新版本的磁盘检查很硬 |

### 三个必须绕过去的坑

**① 新模拟器要求 7.2 GB 空闲才肯建 userdata。**
`FATAL | Not enough space to create userdata partition. Available: 6413 MB, need 7372.80 MB`。
这个 7372.80 MB 是常量：改 `config.ini` 的 `disk.dataPartition.size`（试过 1536M / 2G / 6G 三种写法）、
传 `-partition-size`、换 API 30 镜像、换设备定义，**数字一动不动**。

绕法：自己造一个 2 GB 的 ext4 镜像，用 `-data` 显式指定，跳过"创建"这一步。
```bash
truncate -s 2G u34.img && sudo /sbin/mke2fs -t ext4 -F -q u34.img
emulator -avd p34 -data /var/tmp/u34.img -accel off -skin 720x1280 \
  -gpu swiftshader_indirect -no-window -no-audio -no-boot-anim -no-snapshot
```

**② 官方 APK 只带 `arm64-v8a`，x86_64 模拟器直接拒装。**
沿用 10-22 的老办法：剥 `lib/` + `META-INF/` → `zipalign` → `apksigner` 用临时 key 重签。
`LlamaJni` / `TerminalJni` 都是懒加载 + try/catch 降级，缺 `.so` 只影响本地推理和内置终端，界面照常。
36.7 MB → 23 MB。

**③ `adb shell screencap` 截出来全黑（6358 字节），但 `adb emu screenrecord screenshot` 正常。**
前者走 guest 的 SurfaceFlinger，在 TCG + swiftshader 下拿不到帧；后者走宿主侧渲染。
本报告所有截图都来自后者。

### 环境代价

| 项 | 实测 |
|---|---|
| 冷启动到 `sys.boot_completed=1` | **约 5 分钟** |
| 应用首帧 | 45–75 秒 |
| 单次 `uiautomator dump` | 3–8 秒 |
| SystemUI | 反复 ANR（`System UI isn't responding`），每次要手动点「Wait」 |

**结论：能自动化，但一次完整回归要按"分钟"排期，不适合塞进 CI。**

## 二、验证结果

设备：Android 14（`UE1A.230829.036.A1`，`sdk_phone64_x86_64`，userdebug），720×1280 / 320dpi，
AOSP 镜像（**无 GApps**），APK `versionCode=724`（CI run 43482853049 产物，剥库重签）。

### 通过（有实测证据）

| # | 判据 | 实测证据 |
|---|---|---|
| P11-1 | 开关打开 → 通知 + 形象贴右 | 窗口 `appop=SYSTEM_ALERT_WINDOW`、frame `[636,817][720,901]`；通知 `channel=agentkit_pet_overlay` `importance=2` `flags=0x62`（常驻/静音/不可清）`actions=1`；`isForeground=true foregroundId=20549` |
| P11-2 | 拖动后自动吸边 | 右→左：`[636,817][720,901]` → `[0,817][84,901]`；左→右：`[0,817][84,901]` → `[636,817][720,901]`。两端都是**精确贴边**（x=0 / x2=720） |
| P11-3 | 点形象展开、形象不动 | frame `84×84` → `296×205`，右下角 `(720,885)` 保持不动，只有左上角外扩——正是"窗口长在形象外侧"的设计 |
| P11-4 | 点输入框弹键盘、气泡不被顶出屏幕 | 点形象展开后 IME 弹出，气泡完整停在键盘上方（`parent` 高度从 1220 收到 885）。**AOSP 上通过；ROM 差异仍未覆盖** |
| P11-7 | 「⋯」→ 打开主应用 / 关闭桌面助手 | uiautomator 抓到两项文本，坐标可点 |
| P11-8 | 关闭 → 形象、通知、开关全清 | 点击后：悬浮窗 0、通知 0、`ServiceRecord` 0、`pet_overlay_v1.xml` 里 `enabled=false` |
| P11-9 | 关掉后划掉 App 再开，不复活 | `am force-stop` + 重开：悬浮窗 0、服务 0、开关仍 false |
| P11-10 | 开关开着时进程被杀，桌宠自己回来 | `am kill` 后 40 秒：进程重建、`PetOverlayService` 记录回来、悬浮窗回到 1 个（`START_STICKY` 生效） |
| P11-5（部分） | 发送链路不是哑的 | 气泡内输入 `hello` 发送 → 气泡里出现 `Unable to resolve host "api.openai.com"`。**错误是可见的、不是静默**；模型不可达，因此"有回答 + 朗读"这一段没验到 |
| P13-1（部分） | 磁贴被系统识别 | `pm query-services -a android.service.quicksettings.action.QS_TILE` 返回 `com.beichen.polaris.pet.PetTileService`，`nonLocalizedLabel=北辰`、带 icon |
| P13-3 | 一键唤起不弹键盘 | 对运行中的服务发 `action.LISTEN`：气泡展开、**不弹软键盘**；对比"点形象展开"是弹键盘的 |

### 这轮最值钱的一个发现

```
W ActivityManager: Foreground service started from background can not have
location/camera/microphone access: service com.beichen.polaris/.pet.PetOverlayService
I ActivityManager: Background started FGS: Allowed [... targetSdkVersion:28 ...]
```

**Android 14 会把"从后台启动的前台服务"的麦克风权限关掉**，而且**不看你 targetSdk 是不是 28**。
`spec §11.5` 里写的"targetSdk 28 下不应触发"是**错的**——平台策略按 `uidState` 判，不按 targetSdk 豁免。

影响面：

| 入口 | 是否用户交互 | 麦克风 |
|---|---|---|
| 点通知上的「说一句」 | 是（`tempAllowListReason: fg-service-launch`） | 可用 |
| 点快捷设置磁贴 | 多数 ROM 算用户交互 | 大概率可用，**要真机确认** |
| `START_STICKY` 自愈重建 | **否** | **被平台拒绝** |
| 第三方 App / 广播拉起 | 否 | 被平台拒绝 |

也就是说：**桌宠被系统重建之后，能显示、能打字，但不能再说话**——用户看到的是"点了麦克风没反应/报错"。
现有代码的错误映射会把这类失败说清楚（不是静默），但体验上确实是退化。

这条只有跑起来才看得见，静态守卫抓不到。已记入待办：要么在 `START_STICKY` 重建后不自动开麦（现状已是"用户点了才录"，
所以实际影响是"重建后第一次长按说话"可能失败一次），要么按 spec §11.5 的方案把 FGS 类型补上 `microphone`。

### 没验到（不是失败，是这台机器验不了）

| 项 | 为什么 |
|---|---|
| P11-6 | 需要模型可达（网络到不了 OpenAI） |
| P11-5 的"朗读"部分 | AOSP 镜像没有 TTS 引擎 |
| P12-1 ~ P12-9 | `pm query-services -a android.speech.RecognitionService` → **No services found**；也没有音频输入。只有"无识别服务 → 明确提示"这条降级路径存在（`PetVoice.kt:195-198`），但 5 秒瞬时提示在 TCG 上一次 dump 就错过了 |
| P13-2 / P13-5 / P13-6 / P13-7 / P13-8 / P13-9 | 需要点磁贴 / 点通知按钮 / 锁屏 / 撤销悬浮窗权限——`cmd statusbar` 在这个 build 上只有 expand/collapse，没有 add-tile/click-tile；SystemUI 又在反复 ANR |
| P11-4 的 ROM 差异 | 国产 ROM 的输入法行为 |

### 顺带确认的一条设计约束

直接用 `am start-foreground-service -a ...action.LISTEN` 拉起服务、但开关是 `false` 时，**窗不会建**（服务在 `onCreate` 里 `stopSelf`）。
换句话说：**磁贴/通知必须走 `PetState.start(ctx, action)` 那条路**，绕过它就只有"叫出来但不听"或者"根本不出现"。
这正是守卫 I8 想钉住的东西，现在有了运行时证据。

## 四、复现步骤

```bash
# 0. 一次性准备（这台机器上已就绪，重启后需重来，AVD 在 /var/tmp）
export ANDROID_HOME=/data/home/android-sdk ANDROID_AVD_HOME=/var/tmp/avd
echo no | avdmanager create avd -n p34 -k "system-images;android-34;default;x86_64" --force
truncate -s 2G /var/tmp/u34.img && sudo /sbin/mke2fs -t ext4 -F -q /var/tmp/u34.img

# 1. 启动（约 5 分钟）
emulator -avd p34 -data /var/tmp/u34.img -accel off -skin 720x1280 \
  -gpu swiftshader_indirect -no-window -no-audio -no-boot-anim -no-snapshot &

# 2. 装包（官方包只有 arm64，必须剥库重签）
BT=$ANDROID_HOME/build-tools/34.0.0
cp app-release.apk base.apk && zip -q -d base.apk "lib/*" "META-INF/*"
$BT/zipalign -f -p 4 base.apk aligned.apk
$BT/apksigner sign --ks test.jks --ks-pass pass:android --out signed.apk aligned.apk
adb install -r -g signed.apk
adb shell appops set com.beichen.polaris SYSTEM_ALERT_WINDOW allow

# 3. 开关（正式路径是设置页开关；脚本里可直接写 pref，省掉 UI 摸索）
adb root
adb shell "printf '<?xml version=\"1.0\" encoding=\"utf-8\" standalone=\"yes\" ?>\n<map>\n    <boolean name=\"enabled\" value=\"true\" />\n</map>\n' \
  > /data/data/com.beichen.polaris/shared_prefs/pet_overlay_v1.xml"
adb shell chown 10141:10141 /data/data/com.beichen.polaris/shared_prefs/pet_overlay_v1.xml
adb shell am start-foreground-service -n com.beichen.polaris/com.beichen.polaris.pet.PetOverlayService

# 4. 看结果
adb shell dumpsys window windows | grep -A2 "appop=SYSTEM_ALERT_WINDOW"
adb shell dumpsys notification --noredact | grep "pkg=com.beichen.polaris"
adb emu screenrecord screenshot /tmp     # 注意：不是 adb shell screencap
```
