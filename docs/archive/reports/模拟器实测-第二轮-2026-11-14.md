## 一、这一轮多出来的两把钥匙

### 1. 自己写一个识别服务（P12 的钥匙）

上一轮卡在 `pm query-services -a android.speech.RecognitionService` → `No services found`，
于是 P12 整段判死。其实**系统缺的不是「识别能力」，缺的是「一个声明了 RecognitionService 的进程」**。
`SpeechRecognizer.isRecognitionAvailable()` 只查有没有服务，不查它会不会认字。

于是写了一个 20 KB 的桩：`com.beichen.debug.stt`，继承 `RecognitionService`，
行为由系统属性 `debug.stt.mode` 决定，`adb shell setprop` 随时改，不用重装：

| `debug.stt.mode` | 桩的行为 |
|---|---|
| `result` | 300ms `beginningOfSpeech` → 1.1s `endOfSpeech` → 1.5s `results("现在几点")` |
| `nomatch` | 1.5s `error(ERROR_NO_MATCH)` |
| `speech_timeout` | 1.5s `error(ERROR_SPEECH_TIMEOUT)` |
| `client` / `busy` | 对应的错误码 |
| `hang` | **什么都不回**（测 App 侧硬超时与取消） |

配套还有 `debug.stt.text`（返回什么文本）、`debug.stt.delay`（多久回）。
让它生效：

```bash
adb install -r -g stt.apk
adb shell settings put secure voice_recognition_service com.beichen.debug.stt/.StubRecognizer
adb shell pm query-services -a android.speech.RecognitionService   # 1 services found
```

**它验的是什么、不是什么，必须说清楚：**

| 能验 | 不能验 |
|---|---|
| App 的调用链（`createSpeechRecognizer` → `startListening` → `onResults/onError` → 收尾） | 识别质量、语言、静音阈值（P12-3 仍必须真机） |
| 错误码到中文文案的映射（`errorText`） | 真实音频路径：桩不碰麦克风，`RECORD_AUDIO` 只在系统侧 |
| 20 秒硬超时 / 5 秒结果等待 / 取消与租约释放 | 朗读打断（P12-5，本镜像无 TTS）、音频焦点 ducking（P12-6）、他应用占用麦克风（P12-7） |
| 「识别文字进气泡并自动发送」这一步 | 真机 ROM 的引擎差异 |

换句话说：**它能把「代码写错了」这一类问题挡在真机之前，但挡不住「真机上好不好用」。**

### 2. 磁贴其实是能点的（P13 的钥匙）

上一轮写「`cmd statusbar` 在这个 build 上没有 add-tile」，**这句是错的**。这个 build 有：

```
Status bar commands:
  ...
  add-tile COMPONENT
  remove-tile COMPONENT
  click-tile COMPONENT
```

上一轮失败的真正原因是两条，都不是命令不支持：

1. **`dumpsys statusbar` 里看不到 tile 列表**（Android 14 把 tile 状态挪进了 SystemUI 的 `QSTileHost`），
   于是误判成"没加上"。实际上 `add-tile` 成功后会写进 `Settings.Secure.sysui_qs_tiles`，
   并归一化成 `custom(com.beichen.polaris/.pet.PetTileService)` —— 看 `logcat | grep QSTileHost`
   能看到 `Loaded tile specs from setting: custom(...)`。
2. **`click-tile` 走不通，但真实点击可以**。`click-tile` 在这台机器上没有转发到 TileService
   （`mTileList` 只在 SystemUI 侧维护）。改成真手势：`input swipe 360 8 360 1000 400` 拉开面板，
   截图定位磁贴，`input tap` —— 通了。

顺带踩到一个坑：**磁贴的屏幕坐标随面板高度变**（第一行 86px、第二行 176px）。
上一轮按固定坐标点，点到了设置齿轮上，于是"什么都没发生"。

## 三、两个更正，一条观察

### 更正 1：上一轮说「该 build 不支持 add-tile」——错的

见第一节第 2 条。`cmd statusbar` 三个磁贴子命令都在。真正难的是"知道点哪儿"。

### 更正 2：`mPolicyVisibility=false` —— 悬浮窗被 keyguard 扣住了

本轮后半段悬浮窗一直 `surface shown=false alpha=0.0`，`dumpsys window` 里写着
`mPolicyVisibility=false mAppOpVisibility=true`。同时应用日志反复出现
`[PetTile] 磁贴：锁屏中，先要求解锁` —— 屏幕是 Awake、桌面也画出来了，但
`KeyguardManager.isKeyguardLocked` 一直为 true。**窗口没问题，是被锁屏压住了。**

`locksettings set-disabled true` 反而让它更糟（系统状态卡在"禁用中的锁屏"），
这条命令在真机上不要用来"绕锁屏"。上一轮的 P11 截图（贴边、展开、气泡报错）是在锁屏未介入时拍的，
本轮复现不了同样的画面，但 P11 那些结论不受影响。

### 观察：引擎首次 bind 会吃掉硬超时

桩侧日志显示 `StubSTT: service created` 出现在 `startListening` 之后 6 秒（TCG 上），
而 App 的 20 秒硬超时从 `start()` 就开始计时。真机上这个 bind 是 1–2 秒，
但**低端机 + 第一次唤起**的组合下，"20 秒没说完就停"可能被冷启动吃掉一大截。
现在没有证据说这是 bug，记在这里，等真机上看一眼 P13-4 的首次延迟。


## 五、续：接上一个假模型，把「完整回合」也验掉

第二条卡点是模型不可达（云机到不了 `api.openai.com`），于是「问一句 → 有回答」这条从没跑通过。
补法很土：在云机起一个 60 行的 OpenAI 兼容端点（`/tmp/mock-llm.py`），只做三件事——
把请求原样落盘、问「刚才我问了什么」时从历史里捞上一条、其余回固定文本。

连接走 `adb reverse tcp:18080 tcp:18080`，App 里把 baseUrl 填 `http://127.0.0.1:18080/v1`。
（先试过 `http://10.0.2.2:18080`，气泡里直接报 `Failed to connect to /10.0.2.2:18080`——
这条 NAT 在本机不通，`adb reverse` 更省事。顺带也说明**错误是可见的**。）

### 顺带看出来的两个问题

**① 第二轮请求的 system prompt 出现了两次。**

```
req1  roles: [system, user]                              ← system 304 字符
req2  roles: [system, system, user, assistant, user]     ← 两个一模一样的 system
req3  roles: [system, assistant, user, assistant, user]  ← 又只剩一个，但最早的 user 被裁掉
```

`PetAgentSession.kt:141-142` 把 `loop.send()` 返回的整段上下文（**里面含 system**）存进 `history`，
下一轮再作为 `prior` 传回去，loop 又 prepend 一次自己的 `systemPrompt`。
第三轮看起来"好了"，是因为 `takeLast` 裁剪顺带把旧 system 挤掉了——不是修好了，是碰巧。

影响不大但没必要：每次多付 304 字符的 prompt，且模型会看到两份同样的指令。
一行就能收口：`history.addAll(messages.filterNot { it is SystemMessage }.takeLast(MAX_HISTORY))`。
**这台机器跑不了全量 QA，所以没改**，记在这里。

**② 点通知「说一句」之后，通知面板不收起。**

回合在面板底下完成（日志能证明），但用户看不到气泡，得自己往回拉。
磁贴那条路径上系统会收面板，通知这条路不会——`PendingIntent` 走的是 Service，不是 `startActivityAndCollapse`。
判据 P13-6 只要求"与 P13-3 一致"，严格说通过；体验上是个待办。
