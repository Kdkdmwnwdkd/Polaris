# 同类 Agent 架构横向对比 · 2026-11-18

> **一句话结论：Polaris 缺的不是功能，是「一个回合的状态该由谁保管」。**
> 别人家的桌宠是**主会话的投影**，我们的桌宠是**第二个 Agent**；
> 别人家的动作有**回执**（点了之后屏幕变没变），我们的 `ui_tap` 只回「已点击」；
> 别人家的权限**不跨会话继承**，我们的「不再询问」是永久的。
> 这三处都不是代码量问题，是**所有权问题**——正好是 v4 里 `AgentRuntime` 要解决的那件事。

---

## 0. 为什么现在做这件事

上一轮专家团给出的 v4 方案是**从内部矛盾推出来的**（3 处 loop 构造、两套历史、审批分裂）。
这篇是**从外部反证**：同样的问题，别人怎么解；解法和他们的约束绑不绑得死；我们换了约束之后该长什么样。

方法：只读公开 README / 设计文档 / 行为观察，**不复制任何实现**。每条都标了许可，标「闭源」的只有公开文档可读。

| 样本 | 类别 | 许可 | 为什么选它 |
|---|---|---|---|
| [dsh-live2d-mao](https://github.com/xkk6663/dsh-live2d-mao)（Mao-pet） | 桌宠 · 状态镜像 | MIT | 你点名的那只；12 态 phase 是目前最细的公开口径 |

## 1. 五种范式：他们各自把「状态」放在哪

这是全文最重要的一张表。**所有架构分歧，最后都落在「谁持有回合状态」这一格。**

| 范式 | 代表 | 状态持有者 | 桌宠/UI 拿到什么 | 代价 |
|---|---|---|---|---|
| **A. 镜像** | Mao-pet | 宿主（DSH）；桌宠**零状态** | 12 态 phase 事件 + 逐 token 流 | 桌宠不能替你干活 |
| **B. 中央状态池** | Mobile-Agent-v3 | `InfoPool` 一份可变对象 | 读同一份池子 | 四个角色抢写，靠约定不靠类型 |
| **C. 事件日志** | OpenHands | 追加型 EventLog（唯一可变是 ConversationState） | 订阅事件流，可回放 | 事件体积大，要 condense |
| **D. 单循环 + 多入口** | droidrun / Claude Code | 一个 loop；subagent 是**隔离子上下文** | 只拿摘要，不拿全量 | 摘要会丢细节 |
| **E. 双循环** | **Polaris 现状** | **两个 loop 各自持有** | 各看各的 | **状态分裂、审批分裂、并发失控** |

Polaris 现在落在 E。这不是「实现得不好」，是**没有范式**——`ChatViewModel` 和 `PetAgentSession` 各自 `RealAgentLoop(...)`，谁也不从属于谁。

### 1.5 还有一整类没进上表：把「引擎」搬进手机

DSH 生态那七种实现（JNI 内嵌 libnode / proot 整装 Ubuntu / Termux 快照 / 纯远程客户端）走的是**同一条路**：
> 不改 Agent，改运行环境——把电脑上那个 Node 进程原样塞进手机，插件生态就白拿了。

这条路的隐含前提是「Agent 的智能在插件和模型里，宿主只是个容器」。所以它们能接受 110MB~1GB 的体积、能接受启动慢、能接受后台被系统杀。

**Polaris 走的是反向选择**：不搬引擎，用 Kotlin 重建一个「只做手机原生能力」的 Agent。代价是拿不到插件生态（这是已知的、写进 DSH 文档的取舍），收益是 39MB、冷启动秒级、无障碍/通知/Shizuku 是一等公民。
**这条反向选择是对的，不该动摇**——但要承认它的代价：**所有「Agent 该怎么组织」的问题，都得自己解**，没有上游帮你踩坑。这正是本文要向外看的原因。

## 2. 逐项拆：我们 vs 他们

### 2.1 回合所有权

| | Polaris | 对比对象 |
|---|---|---|
| 主界面 | `ChatViewModel.kt:2055` 起 loop，`TurnObservers.production()` | Claude Code：单 loop，subagent 只回摘要 |
| 桌宠 | `PetAgentSession.kt:39` 「一条 RealAgentLoop + 一份**内存内**历史」，`:151` 构造 | Mao-pet：**不持有 loop、不持有窗口**，只 `POST /api/plugin/dsh/ingest` |
| 子代理 | `SubAgentLogic.kt:33` `MAX_TASKS = 3`，自建并发 | droidrun：Manager 串行调度 Executor 的**单个**动作 |

**关键差异不是「谁更强」，是「谁对状态负责」。**
Mao-pet 那套之所以能「装完不用配」，正是因为它**什么都不持有**——DSH 是唯一真源，桌宠只是显示器。
我们的桌宠能独立办事（这是真需求，不该砍），但它**顺带**也持有一份历史，于是同一句话在两处有两条时间线。

### 2.2 动作之后：有没有回执

这是本次对比里**最便宜、收益最大**的一条。

| | 做法 | 我们的现状 |
|---|---|---|
| droidrun | 每次动作后 `wait 0.5s` → 比较屏幕状态 → 不 stable 就继续等，直到超时；下一步上下文里同时放**前一张树 + 当前树**（差分） | 无 |
| Mobile-Agent-v3 | `ActionReflector` 比前后截图 → 给 A（成功）/ B（跳错页）/ C（没变化）三级；**连续 2 次 B/C 才**上报 Manager 重规划 | 无 |
| **Polaris** | `UiAutomationTools.kt:231` `okMsg = "已在 ($x, $y) 点击"` | 只证明**动作已下发**，不证明**界面变了** |

实证代码（同一份 `runOnService` 包装了 tap / long_press / swipe / input / key 五个工具）：

```kotlin
// app/src/main/java/com/beichen/polaris/automation/UiAutomationTools.kt:57-61
val ok = withContext(Dispatchers.Main) { block(svc) }
if (ok) ToolResult.ok(code = okCode, message = okMsg)   // ← 到这里就返回了
else shizukuFallback(shizukuCommand, okCode, okMsg) ?: ToolResult.fail(...)
```

`dispatchTap()` 返回 `Boolean` 的含义是「事件注入成功」，不是「目标响应了」。模型只能靠下一步再调 `ui_tree` 自己发现——**多花一次 LLM 往返，还可能误判成「点了没反应，再点一次」**。

### 2.3 上下文与持久化

| | 做法 |
|---|---|
| Claude Code | 五层渐进压缩：budget 截断 → snip 老段 → microcompact（缓存感知）→ context collapse（读时投影）→ auto-compact（模型摘要）。**先轻后重**。 |
| OpenHands | Condenser 产出 `CondensationSummaryEvent`，被压缩的事件仍在日志里，只是不再进 LLM 视图。 |
| Polaris 内存侧 | `ContextBudget.kt` 已经很好：token 估算、剥图、**按整步丢弃**、保留首条用户消息、保证 `tool_calls ↔ tool` 配对。这块不输。 |
| Polaris 落盘侧 | `ConversationStore.kt:62` `MAX_FIELD_CHARS = 4000`，`:181/:188/:193/:203/:206` 对所有正文 `take(4000)`，**无标记** |

内存侧工具结果上限是 `MAX_TOOL_RESULT_CHARS`（24k，`ContextBudget.kt:101-108`），落盘只有 4000——**同一份对话两套保真度，差 6 倍**。

> 这不是「压缩策略不好」，是**持久化把压缩结果当成了真源**。Claude Code / OpenHands 都把「视图」和「存档」分开；我们把它们混在了一起。

### 2.4 权限

| | 语义 | 跨会话 |
|---|---|---|
| Claude Code | **deny 永远压 allow**；工具先被过滤出模型视野；权限模式分 7 档 | **不恢复**——「trust is always re-established」 |
| **Polaris** | `ApprovalScope.allows` 按作用域记忆，「不再询问」长期有效 | **恢复**，且默认全开：`ApprovalScope.kt:139` — `if (toolName !in SHELL_TOOLS) return ApprovalGrant(..., memorizable = true)`，**除 shell 外所有工具默认可记忆**，含 `github_commit` |

Claude Code 有一条实证值得抄进威胁模型：**用户对权限弹窗的同意率是 93%**——所以 Anthropic 的结论不是「加更多警告」，而是「上自动分类器 + 收紧默认」。手机端弹窗成本更高、用户更容易无脑点，这条对我们更成立。

### 2.5 事件模型

| | 有几套事件 | 谁消费 |
|---|---|---|
| OpenHands | 1 套（Action / Observation，append-only） | Controller、Server(WebSocket)、Runtime、Memory 各自订阅 |
| Mao-pet | 1 套（DSH 会话事件 → 12 态 phase） | 桌宠渲染层 |
| **Polaris** | **3 套**：`AgentEvent`(4，UI 驱动) / `Hooks`(4 时机) / `TurnEvent`(8，排障) | `AgentEvent` → UI；`TurnEvent` → `TurnObservers.production()` 只落 ndjson，**app 层零消费者** |

`TurnObserver.kt:44` 的注释写得很清楚：「三者职责不同，故并存」。这个判断在当时是对的。但现在的问题是：

- `TurnEvent` 已经**落盘**（`TurnEventNdjson.kt`），却没有任何投影；
- 桌宠要的「现在在干嘛」，只能去问 `PetAgentSession` 内部，而不是订阅事件。

也就是说：**事件已经有了，缺的是「从事件推导状态」的那一层纯函数**。这一层做完，桌宠、通知栏、审计、MCP 状态查询可以共用一份。

### 2.6 工具面

| | 工具数 | 组织方式 |
|---|---|---|
| OpenHands | 4（bash / python / editor / browser） | 「代码是通用动作」，靠组合 |
| droidrun | 11 个原子动作 + **App Cards**（每个 App 一份用法知识） | 知识按需注入，不占常驻上下文 |
| Polaris | **57**（`ToolCatalog`），默认面 525 token | 按组暴露，`ToolExposurePolicy` |

57 个不算多——手机端没法「写代码绕过」，专用工具是必要的。真正可借鉴的是 **App Card**：把「微信怎么发朋友圈」这类知识从系统提示挪到按需加载。我们已经有 `use_skill` / `LoadSkillTool`，缺的是「按当前前台包名自动挂一张卡」这一步。

### 2.7 打断

| | 做法 |
|---|---|
| Open-LLM-VTuber | VAD 状态机（IDLE/ACTIVE/INACTIVE）+ `asyncio.Task.cancel()` + TTS 队列清空，**任意环节可打断**，亚秒级 |
| Polaris | `MicClaim`（音频租约）已有；但「打断后这一回合怎么收尾」没有对应契约 |

这条只列出来，不展开——手机端语音不是当前瓶颈，但它和 §2.1 是同一个问题的另一面：**取消了，谁来保证状态收敛**。

## 3. 五件该做的事（按性价比排序）

每件都写清楚：**他们的做法 → 他们的约束 → 我们的约束不同 → 我们的落点**。

### ① 给所有 UI 写操作加「动作后回执」——2~3 天，最高性价比

- **他们**：动作后等屏幕稳定 + 比状态，产出 A/B/C 或差分树。
- **他们的约束**：只有截图（droidrun 走 Portal+ADB，Mobile-Agent 走 ADB），所以必须用 VLM 或像素 diff，贵。
- **我们的约束不同**：我们有 `UiNodeSummary`（index/text/desc/resId/depth/clickable/parentIndex/bounds，`AgentAccessibilityService.kt:93-101`），**不用截图就能 diff**；而且 `waitForFreshWindow` 的轮询骨架已经有了（`:455-479`）。
- **落点**：`runOnService`（`UiAutomationTools.kt:40-68`）是五个写操作的唯一出口，**只改这一个函数**：
  1. 动作前取一次轻量指纹（节点数 + 前 N 个 `text|resId` 的哈希）；
  2. 动作后轮询到「指纹变化」或 600ms 超时（复用现有 `delay(pollMs)` 骨架）；
  3. 返回改成 `tap_ok`（变了）/ `tap_no_effect`（没变，附「可能原因：坐标落在不可点区域 / 弹窗遮挡 / 页面未加载完」）。
- **不要做**：不要为它新增工具、不要上截图比对、不要引入新依赖。
- **验收**：`tap_no_effect` 出现时，模型下一句不再说「已点击」而是重试或换路。可用一条 harness 断言：注入一个空点击，结果码必须是 `tap_no_effect`。

### ② 桌宠改成「双模式」：默认镜像，显式才独立——依赖 ①，约 5~8 天（含 ① 之后）

- **他们**：Mao-pet 的桌宠**只推事件、不持有窗口**（npm 包描述原文）；状态来自 DSH 真实事件，不是定时器假循环。
- **他们的约束**：DSH 是唯一执行体，桌宠没必要也不能替它决策。
- **我们的约束不同**：桌宠「能自己办事」是真需求（锁屏、通勤、不想开主界面）。
- **所以不是二选一，是分两个模式**：
  - **镜像模式（默认）**：不起 loop。订阅 `TurnEvent` + `AgentEvent`，用**纯函数**折叠成 phase（见 ③），驱动表情 + 气泡。零历史、零审批、零并发。
  - **独立模式（显式）**：保留现在的 `PetAgentSession`，但**必须**经由 `AgentRuntime` 拿许可（v4 §3.2 的两级并发），不再自建 loop。
- **落点**：`PetAgentSession.kt:39` 的类注释改成两种模式；`:151` 的 `RealAgentLoop(...)` 只在独立模式执行。
- **验收**：主界面跑一个回合，桌宠气泡在 <300ms 内出现「正在用 read 干活」；此时 `adb shell ps` 里没有第二个 loop 的协程栈。

### ③ 把 `TurnEvent` 升格为「投影源」，phase 用纯函数推导——2~3 天

- **他们**：Mao-pet 的 12 态（规划/思考中/执行工具/回复中/聆听/说话/待确认/完成/出错/暂停/待机/在线）是从事件折叠出来的，**不是每个模块自己 set 一个状态**。
- **我们的约束不同**：我们已经有 8 个 `TurnEvent`（`TurnObserver.kt:44`），而且已经在落 ndjson——不需要新建总线。
- **所以做法是**：新增 `core/agent/TurnPhase.kt`，`fun phaseOf(events: List<TurnEvent>): Phase`，纯函数、零 Android 依赖、可单测。
  - `ToolCallStarted` 且未 `ToolCallEnded` → `执行工具(tool)`
  - `LlmCallStarted` 未 End → `思考中`
  - `StepClosed` 且后续无事件 → `回复中`
  - `TurnEnded(ok/err)` → `完成/出错`
- **不要做**：不要为了桌宠再加第四套事件；不要把 phase 塞进 `TurnEvent`（它是排障口径，加了会污染）。
- **验收**：给 `phaseOf` 写 8 条 JUnit（这是全仓第 2 个 JUnit 测试，见 v4 §5 的迁移建议）。

### ④ 给「可记忆授权」加边界——1~2 天，安全线

- **他们**：Claude Code 权限**不跨会话恢复**；deny 压 allow；默认最小。
- **他们的约束**：桌面端弹窗便宜，且用户 93% 会同意——所以宁可每次重问。
- **我们的约束不同**：手机端弹窗更烦，全量重问会毁体验；但「永久记住」等于把 P1-1（相对路径绕过）的风险放大到无限期。
- **所以是折中，不是照搬**：
  - `ApprovalScope` 的记忆加 **TTL**（默认 30 分钟）或**回合数上限**（如 20 回合）；
  - 工具**升级**（只读→写、写→发）时强制失效；
  - `github_commit` 进 `EgressGuard.DEFAULT_EGRESS_TOOLS`（v4 P0 已有这条）。
- **落点**：`core/agent/ApprovalScope.kt:139`。
- **验收**：静态不变量——`DEFAULT_EGRESS_TOOLS` 必须包含 `ToolCatalog` 里所有 `Approval.GIT_WRITE` 的工具（一条脚本反查即可，`ToolCatalog.kt:183` 就是 `github_commit`）。

### ⑤ 上下文档位：把「视图」和「存档」分开——2~3 天

- **他们**：OpenHands 压缩后事件仍在日志；Claude Code 压缩只影响发给模型的视图。
- **我们的错误**：`ContextBudget` 算出了「这一轮该发什么」，但 `ConversationStore` 把「存什么」定成了 4000——**两个决策互相不知道**。
- **做法**（复用现有结构，不新建存储）：
  - `MsgRecord` 加 `truncated: Boolean` + `origChars: Int`（**先加标记，不改容量**，1 天，立即可做）；
  - 工具结果正文外置到分片旁的 `<turnId>.tool.jsonl`，`MsgRecord` 只存引用 + 首 200 字符摘要（2 天）；
  - `ConversationShard` 已只存 `turns`（真源），`messages` 是现算——这条路径本来就是对的方向，别动。
- **验收**：重启 App 后打开一个长工具结果的会话，UI 上能看到「已截断，原文 18,432 字符」而不是静默少一半。

## 4. 三件明确**不要**照抄的事

| 不要抄 | 理由（数字） |
|---|---|
| **Node 内嵌 / proot 整装** | DSH-Android 110MB 包 + 500MB 空间起步，proot 路线 1GB。Polaris release 39MB。体积翻 3 倍换插件生态，和「手机原生 Agent」的定位冲突。 |
| **纯截图 + 坐标点击** | droidrun / Mobile-Agent 只能这么做（它们从设备外部看屏幕）。我们有 `ui_tree`，**结构化树比像素稳、比截图省 token**。学它们的「验证时机」，别学它们的「感知方式」。 |
| **deny-first 全量** | 手机端弹窗疲劳比桌面更严重。我们要的是「记忆有边界」，不是「每次都问」。 |

另外，两条许可红线（DSH 生态文档里已列，这里重申）：`dsh-Go` 是 AGPL-3.0、`DSHBox` 是 GPL-3.0，**只可读思路，不可复制实现**；本文引用的六项里，Claude Code 闭源，只有公开文档可读。

## 5. 对 v4 路线图的修订

原 v4 是 P0 止血 → P1 骨架。加入外部证据后，只调顺序，不加新工程：

| 阶段 | 原计划 | 修订 |
|---|---|---|
| **P0** | shell 相对路径、落盘标记、`github_commit`、L0 变异门禁 | **加：① 动作回执**（2~3 天）。理由：它是唯一一个「不改架构就能拿到体验提升」的项，且能顺手给 L0 提供一条真行为断言（现在是全 SKIP）。 |
| **P1** | `AgentRuntime`、`Consent v2`、`ToolAssembler` | **加：③ phase 纯函数**（2~3 天，属于 core，可与 Runtime 并行）；**② 桌宠双模式**放到 Runtime 落地之后，作为它的第一个消费者——**用它来验证 Runtime 是否真的拿到了所有权**。 |
| **P2** | 账本、MCP 写档 | **加：⑤ 工具结果外置**；**④ 授权 TTL** 提前到 P1（安全项不该等）。 |
| **不做** | `UiItem → TurnEvent` 全量迁移 | 维持。本次对比进一步支持这个判断：OpenHands 的收益来自「单一真源 + 可回放」，不是「换一种 UI 模型」——而我们的 `ConversationShard` 已经只存 `turns` 了。 |

## 6. 我不确定的

1. **droidrun 的「等屏幕稳定」在低端机上的实际耗时**——README 只说 0.5s 起等，没给 P95。我们如果照 600ms 超时，在千元机上可能偏短，需要真机标定（`docs/qa/真机矩阵-v1.md` 里加一条）。
2. **`tap_no_effect` 的误报率**——有些点击（如下拉刷新）界面指纹变化很小，可能被判成「没生效」。缓解：只对 `clickable=true` 节点的点击做判定，滑动/输入先不做。
3. **Mao-pet 的 12 态是否过细**——它是给 Live2D 表情用的，我们需要几态取决于美术资源。本文按 6 态（思考/执行/回复/待确认/完成/出错）设计，够用即可，别为了对齐而扩。
4. **Claude Code 的「权限不跨会话」在移动端是否可接受**——没有移动端数据，只有桌面端的 93% 同意率。所以 ④ 我给的是 TTL 折中，不是照搬。
5. **Mobile-Agent-v3 的许可**——搜索结果没给明确 LICENSE 字段，标注为「以仓库为准」，本文只引用了它的角色划分（公开论文/文档层面），未引用代码。
