# 端点明文策略：带凭据的请求不许走公网 HTTP

**日期**：2026-11-10　**基线**：`a8a08da`
**对应审计项**：F6（`ConfigStore` 明文存 Key / 备份含明文 / 允许 `http://` 端点）
**本文只解决 F6 的第三条**，前两条见文末「未做」。

---

## 一、问题是什么

Base URL 由用户自己填，全仓没有一处拒绝 `http://`。这对局域网服务是刚需：

- Ollama 默认 `http://127.0.0.1:11434`
- LM Studio / vLLM / one-api 中转站常跑在 `http://192.168.x.x:port`
- 用户拿手机连自家 NAS

所以 `network_security_config.xml` 全局放开了明文（W-46 的决定，理由写在那个文件的注释里：
Android 的 `<domain>` 只接受主机名，表达不了「私网段」）。

同一条放行规则也覆盖了**公网主机 + 明文**：`Authorization: Bearer sk-...` 会以明文经过沿途
每一个热点、每一级链路。一次咖啡店 Wi-Fi 就够把 Key 拿走，用户不会收到任何提示。

## 二、三个候选方案

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A 网段白名单** | 判定主机地址是否落在私网段，落在里则放行明文，否则拒绝 | 纯函数、可逐条对拍、零依赖、不需要证书基础设施；判据只有一处 | 需要自己维护网段表；`http://mynas.com` 解析到公网时判不出来 | **采用** |
| **B 自签证书 / 用户装 CA** | 强制 https，允许用户导入自签 CA | 传输层真加密，最彻底 | 要改 UI 做证书导入、要处理证书过期与轮换、`network_security_config` 得放开用户 CA；局域网设备的自签证书在手机上装一次要过系统警告页，大多数用户走不完 | 不做 |
| **C 全局强制 TLS + 例外清单** | 默认只允许 https，用户显式加例外 | 语义直白 | 例外清单要 UI（ModelConfigScreen 已是冻结文件，2469 行上限），且「例外」一旦被加进去就长期有效，等于把风险改成一次性点击 | 不做 |

三者不是互斥的：B 是 A 的加强版（A 挡不住的「域名解析到公网」它也能挡），但成本高一个量级。
先把 A 落地，B 留作后续（见文末）。

## 三、选型：A，且**只对有凭据的请求拒绝**

两个限定条件，都是刻意的：

**1. 只拒「有凭据」的请求。**
没有 Key 的请求拦下来收益很小（泄漏的是 prompt 本身，不是可复用的长期凭据），
代价却是把用户的可用配置直接打死——比如 keyless 的 llama.cpp 被反代到公网。
判据里 `sendsCredentials = apiKey.isNotBlank() || customHeaders.isNotEmpty()`
（中转站常把 Key 放在 `X-Api-Key`，不在 `apiKey` 字段里）。

**2. 拒绝发生在发请求前，不是保存配置时。**
Base URL 允许先填后改；「测试连接」与真正发请求走同一条判定，早拦会多出一份
可能与这里漂移的规则。真实入口有四条，全部接同一个判据：

| 入口 | 文件 | 失败形态 |
|---|---|---|
| 对话 / 测试连接 | `LLMClient.requireUsableEndpoint` | `LlmHttpException(400)`，不重试 |
| 选择模型（拉 `/models`） | `ModelListFetcher.fetch` | `IOException`，弹窗里直接显示 |
| 查余额 | `BalanceService.query` | `Result.failure` |
| 出图（OpenAI 兼容） | `OpenAIMediaProvider.submit` | `MediaException` |

不重试这点很重要：400 不是网络问题，重试三次只是把同一串 Key 明文再发三次
（`LlmHttpException.retryable` 只对 429/5xx 为真，这里顺带靠它兜住）。

## 四、判据（`core/net/EndpointPolicy`）

| 端点 | 判定 | 说明 |
|---|---|---|
| `https://` 任意 | 放行 | — |
| `http://` + 私网/本机/单标签主机名 | 放行 | 流量不出本机或不出局域网 |
| `http://` + 公网主机 | **有凭据时拒绝** | 文案点名主机并给出三条出路 |

「私网」覆盖：

- **名字**：`localhost`、`*.localhost`、`.local`（mDNS）、`.lan`、`.internal`、
  `.home.arpa`（RFC 8375）、`.localdomain`，以及**不含点**的单标签主机名（`nas`、`my-router`）
- **IPv4**：`127/8`、`10/8`、`192.168/16`、`172.16/12`、`169.254/16`（链路本地，含云元数据地址）、
  `100.64/10`（CGNAT，Tailscale 等组网工具常用）、`0.0.0.0`
- **IPv6**：`::1`、`::`、`fe80::/10`、`fc00::/7`（ULA）、`::ffff:a.b.c.d`（映射地址按内嵌 IPv4 判）

**不做 DNS 解析。** `http://mynas.com` 若在公网 DNS 里解析到公网地址，本类仍判为公网——
判据只回答「字面上这是不是一个私网地址」，那是纯函数能确定回答的唯一问题；要覆盖
「域名指向哪」得联网，会把一个纯判据变成带 IO 的判据，也会让 harness 需要网络。

## 五、行为变化（升级后可能被影响的人）

只有一类：**把公网地址填成 `http://` 且配了 Key** 的用户。他们会看到一条 400：

> 端点「xxx」使用明文 HTTP 且可从公网访问，API Key 会以明文经过沿途网络。
> 请把地址改成 https，或改成本机 / 局域网地址（如 192.168.x.x、10.x.x.x）；
> 服务本身只支持 http 时，请在前面加一层 TLS 反向代理（Caddy / Nginx 均可）。

这不是「兼容性回归」，是这一类配置本身就是泄漏面。代价是这部分用户必须改配置
（加一层反代，或换 https 端点），收益是 Key 不再明文过公网。

预设目录里 30+ 家供应商全部是 `https://`，不受影响；Ollama / LM Studio / 局域网
one-api 走私网判据，不受影响。

## 六、验证

`run-endpoint-policy-verification.sh`：**23 条**，沙箱与 CI 都真跑（不 SKIP）。

- **[A] 形态分类 5 条**：https 一律放行（含大写 scheme、带端口、私网 https）、
  http+私网、http+公网（域名/IP/中转站/IPv6）、畸形（空串/无 scheme/`file:`/`ftp:`/
  `content:`/无主机）、脏输入（首尾空白、userinfo、`?` 与 `#` 后的内容不参与判定）
- **[B] 私网判定 5 条**：IPv4 四类私网段及其**边界**（`172.32`/`172.15`/`11.0.0.1`/
  `192.169` 必须判为公网）、链路本地/CGNAT 及其上界（`100.128.0.1` 必须公网）、
  IPv6（回环/ULA/链路本地/映射地址，`2001:db8::` 必须公网）、名字形态
  （`localhost.example.com` 必须公网）、非法 IPv4 不被误判
- **[C] 拒绝语义 6 条**：有凭据才拒、无凭据放行、私网明文一律放行、https 一律放行、
  畸形不重复报错、完整 URL（`/v1/models?page=1`）同样能判
- **[G] 接线 7 条**：四条链路都真的调了它；自定义头计入判定；判定位置在
  「端点未配置」分支之后（否则空端点会被误报成「公网明文」，用户按提示改也改不好）；
  拒绝落在 400 上

反向变异（人工验过）：把 `isPrivateIpv4` 改成恒 `false` → B1/B2 8 条红；
把 `refusalFor` 改成恒 `null` → C1 与 G1 红。

## 七、未做（仍建议排期）

1. **`ConfigStore` 明文存 Key**。项目在类注释里明确决定了不加密（App 私有目录 +
   「加密无法防御 root 设备」）。这个论证成立一半：root 设备确实挡不住，但
   `MODE_PRIVATE` + 系统备份已关（`allowBackup="false"`）之外，真正的泄漏面是
   **App 内备份包**——见第 2 条。要动存储层，得先决定是否引入
   `androidx.security:security-crypto`（与「零新增依赖」的项目立场冲突）。
2. **备份包含明文 Key**。`BackupUseCase` 把 `profilesJson`（含 `apiKey`）、
   `mediaKeys`、`keyPool.exportAll()` 原样写进 ZIP；GitHub PAT 已在 W-47 里剔掉了，
   理由是「备份件常被存到网盘/微信」。同一条理由对 API Key 一样成立，且恢复侧已有
   可复用的「沿用本机凭据」写法（`restoreFrom` 的 PAT 分支）。
   **这是下一个该做的**，改动面比本条小。
3. **自签证书支持**（方案 B）。局域网设备自签证书是真实需求，但目前没有用户提出，
   且要动 UI 与 `network_security_config`，优先级低于第 2 条。
4. **MCP 远程服务器的端点判定**。`McpServerConfig.url` 同样是用户填的，
   但 MCP 通常不带模型 Key（鉴权方式由服务器自己定），暂未接入。
