# 竞品对标：DSH-Go（DeepSeek Harness 手机版）vs 北辰 Polaris

> 对标时间：2026-11-16 ｜ 对象 `ccch1mneyyy/dsh-Go`（v1.0.9）
> 事实来源：GitHub API（仓库元数据）+ 仓库 README（中文）+ 公开报道。凡标"报道"的为媒体/评测描述，未经我读源码核实。

---

## 0. 一句话

**它不是"我们的替代品"，是同一赛道的对照组：它用"壳 + Node"换来了插件生态，我们用"原生 Kotlin"换来了体积与离线；而它已经做到的三件事——真守卫、审批名单化、屏幕租约——恰好是我们 v3 里挂着的三个洞。**

---

## 1. 它是什么（事实）

| 项 | 值 |
|---|---|
| 仓库 | `ccch1mneyyy/dsh-Go`，2026-10-25 创建，11-16 仍在更新 |
| 热度 | **24,065 star / 1,139 fork / 634 open issues**（一个月） |
| 许可 | **AGPL-3.0**（我们是 Apache-2.0） |
| 语言 | Dart（Flutter UI）+ Kotlin（系统集成）；iOS 用 Swift/WidgetKit 在开发 |
| 平台 | Android 8.0（API 26）起；arm64 为主，另有 x86_64 包，无 32 位 ARM |
| 包体 | **APK 约 180–197MB**；装完本机环境**约 1GB**（媒体口径） |
| 本机运行 | App 私有目录解压 **Ubuntu 24.04 + Node.js + DSH**，走 **PRoot**，免 root、免 Termux |
| 远程运行 | SSH / DSHarness Remote，连电脑或服务器上的 DSH（当前只支持图片附件，不能开网页版，插件只开关，不支持 DS Bot 与日志导出） |
| 模型 | **仍在云端**——"手机上跑的是调度器，模型请求由你配置的提供方处理" |

它和 Polaris 的重合度高得惊人：本机容器、屏幕操控、工具审批、语音输入、桌宠、分享。差别在于**引擎是谁**：
它跑的是 DeepSeek 官方的 TypeScript agent 框架（"一切皆插件"，Cordis 内核），我们跑的是自己写的 Kotlin 引擎。

## 2. 架构对照

| 维度 | DSH-Go | Polaris | 谁更优 |
|---|---|---|---|
| 引擎运行时 | PRoot + Ubuntu + Node.js（DSH/TS） | 原生 Kotlin，无外部运行时 | **我们**（启动、体积、稳定性） |
| 扩展机制 | 插件即一切，原生插件 SDK + 插件市场，电脑手机同步 | 57 个内置工具 + 技能包（JS/Rhino），无插件市场 | **它**（生态位） |
| 包体 / 占用 | ~180MB / 1GB | **~42MB** / 模型按需 24–196MB | **我们**（4 倍体积差） |
| 模型位置 | 纯云端 | 云端 + **端上 llama.cpp** + 端上 ASR/TTS | **我们**（唯一不可替代） |
| 屏幕操控 | 无障碍读屏点按输入；Android 14+ 用 Shizuku/自连 ADB 开**看不见的虚拟屏**（不打扰模式） | 无障碍 + Shizuku + 无线 ADB + proot 容器 | 平：我们通道多，它虚拟屏体验更干净 |
| 审批 | **三档**（每次问 / 本任务免确认 / 始终免确认）+ **App 名单**（支付/银行/券商默认不碰、微信每步确认）+ 解除限制需看全屏免责 + 长按 1.5s + **任务中途锁死** | 参数级审批 + 记忆档 + 不可记忆档 | **它**（见 §3.2） |
| 守卫 | **单调守卫真生效**（只能 deny 或弃权） | 类型写对了，**零实现零装配** | **它**（见 §3.1） |
| 桌宠 | Deepy 小鲸鱼 / 鲸娘，Live2D，随状态动画，可悬浮桌面 | 84dp Canvas 自绘，状态机 | 它（美术与情绪），我们（零素材零依赖） |
| 语音 | 语音输入（走系统/云端） | **自带离线 ASR + 本地 TTS + 声音克隆** | **我们**（真离线） |
| 分享 | 端到端加密**回放链接**，密钥只在链接里 | 导出 `.md` 真文件 | 它（传播性），我们（私密性） |
| 已知短板 | 只有 Android（iOS/鸿蒙适配中）、后台被杀要手动放行、PRoot 兼容层、634 个未关 issue | 无真机验证、文档滞后、0 star | 各有各的债 |

## 3. 它照出了我们 v3 的三个洞

### 3.1 守卫：我们抄了语义，没抄接线

DSH 的工具流水线里，"单调守卫（只能 deny 或弃权）"是**真的在链上跑的**，而且排在审批之前。
DSH-Go 之所以敢把"点手机"这种权限交给 agent，靠的就是这条链 + 三档审批兜住。

我们的对应实现是 `ToolGuardChain`——`GuardDecision` 只有 `Abstain` / `Deny`，文档里那段推理写得比 DSH 还清楚，
但**全仓没有一个守卫实现，`productionSeams` 零调用方**。生产上真正在拦东西的是 `FailureGuard`，它**有** `Allow`。

> 结论：我们不是"还没做"，是"做完了没插电"。而屏幕操控、容器、写文件这些能力一旦上，没插电的守卫就等于没有守卫。
> v3 的 D-3 应该从"P0 里的一条"提到**P0 第一条**。

### 3.2 审批：它的边界是"产品语言"，我们的边界是"参数语言"

它把安全做成用户能理解的三句话：**哪些 App 不碰**（支付/银行/券商）、**哪些要逐步确认**（微信）、**怎么解除**（看完全屏免责 + 长按 1.5 秒 + 任务进行中锁死）。

我们的边界是 `needsApprovalFor(args)` + 记忆档，工程上更精细，但用户感知不到"它不会碰我的支付宝"。
更糟的是有三处漏：`load_skill` 零弹窗就能装技能并执行脚本；`install_base64` 完全不过 URL 校验；
`cat /sdcard/...` 这种只读命令连审批都不弹（`ShellCommandRules` 自己承认"只读不等于无害"）。

> 结论：这不是功能差距，是**边界表达**的差距。DSH-Go 的做法（App 名单 + 解除仪式）成本极低，值得直接借。

### 3.3 资源租约：它给"屏幕"发了租约，我们连"麦克风"都没锁住

它的"不打扰模式"本质是：向系统借一块虚拟屏，用完归还——和我们的 `MicClaim` 是同一个模型：
**稀缺资源 + 单一持有者 + 可撤销租约**。

它已经用这个模型管住了屏幕。我们的 `MicClaim` 逻辑写得很扎实（单调 id、迟到释放按 id 判、`ExternalBusy` 一票否决），
但 `ChatScreen` 自建了第二个 `TtsController`、克隆录音页直接 `AudioRecord`——**两条后门绕过了它**。

> 结论：v3 的"第五状态轴"（模型就绪 / 引擎 handle / 麦克风租约）不是抽象洁癖，是对标里已经有人做到的东西。

## 4. 我们的三个不对称优势（别丢）

1. **端上模型**。DSH-Go 明确"手机只是调度器，模型还在云端"——断网就废。我们有 llama.cpp + sherpa-onnx，
   真能离线跑。这是它短期内不会有的能力（它的引擎是 TS + Node，接不动端上推理）。
2. **体积**。42MB vs 180MB + 1GB。国行机、低端机、存储紧张的用户，这个差是决定性的。
   别为了"插件自由"把 Node 塞进来，那是自毁护城河。
3. **启动与稳定**。它的一半 issue 是"引擎起不来"（鸿蒙直接失败、PRoot 兼容层、后台被杀）。
   我们没有外部运行时，故障面天然小一号——前提是我们自己那堆 Android API 的坑（FGS 类型、targetSdk）别踩爆。

## 5. 值得抄的三件 / 不能抄的两件

**值得抄**

| 做法 | 成本 | 收益 |
|---|---|---|
| 三档确认 + App 名单默认拒绝 | 低（改审批 UI + 一张表） | 用户第一次用就懂"它不会碰支付" |
| 解除限制的仪式（免责全屏 + 长按 + 任务中锁死） | 极低 | 把"放宽"从一次误触变成一个决定 |
| 端到端加密回放链接 | 中（要服务端） | 分享传播性，我们只有导 `.md` |

**不能抄**

| 做法 | 原因 |
|---|---|
| AGPL-3.0 的任何代码 | 我们是 Apache-2.0，代码级借鉴会传染整仓许可；只读思路可以 |
| 把 Node + Ubuntu 全量塞进 APK | 体积从 42MB 变 1GB，唯一优势立刻消失 |

## 6. 对 v3 路线的修订

| 改动 | 原因 |
|---|---|
| **D-3（守卫接线）提到 P0 第一位** | 屏幕操控/容器/写文件的能力已经在，守卫没插电；对标里别人是真跑通的 |
| **P0 新增 D-0：审批名单化 + 解除仪式** | 成本最低、感知最强的一条；顺带把 `load_skill` 的零弹窗通道收进同一套 |
| P3 新增「屏幕租约（虚拟屏不打扰模式）」 | 与 MicClaim 同构，是我们已有抽象的自然延伸 |
| P3 暂不做「插件市场」 | 它的护城河是 DSH 的 TS 生态与 24k 星的分发，我们 57 个工具自研，追不上也不必追 |
| 不做「远程连 PC 上的自己」 | 它的第二形态是"手机当遥控器"，我们的定位是端上闭环；要做也是 P4 之后 |

## 7. 一句冷静的话

它一个月 24k 星，我们 0 星，而我们的代码量是它的数倍、能力面（离线、端上模型、语音克隆）比它宽。
差距不在工程，在**分发与叙事**：它借了 DeepSeek 的名字、官方的"一切皆插件"叙事、和一群愿意点 star 的人。

对标的意义不是"我们要变成它"，而是：**它验证了这个需求是真的，同时也告诉我们，光把能力做扎实不会有人看见。**
这两件事要分开解，别用"再写两万行"去解第二件。
