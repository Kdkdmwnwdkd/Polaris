## 2. 三个必须知道的取舍

### 2.1 `load_skill` 从 SAFE 升到 DANGEROUS，断掉了技能自举

`Capability` 只影响「技能能调用什么工具」。升档后 imported/remote 技能**装不了新技能包**，
只有 packaged 技能与主对话能装。这是有意的：否则一个导入的技能可以再装一个技能，
链式绕过用户在安装那一步的判断。

### 2.2 `use_skill` 刻意**不加**审批

信任根在安装那一步。装配后再逐次弹窗只会把正常使用拖成几十次确认（R-08 的老毛病反过来）。
脚本执行另有闸门：imported 技能 `allowScript=false`，脚本内调工具还要过白名单 + 能力门 +
`SkillNetGrant` 三关。

### 2.3 断言压降 ≠ 守护变强

`assertAllIn` 让「一个 check 里 N 个关键字」只算一条断言。好处是断言总数能反映
「哪些区还有人看着」；代价是**失败定位从「哪一行」降到「哪个 check」**。
它扫的仍然是源码文本，不是行为——真正的行为验证需要编译并跑起来。

### 3.2 五个恒真假绿 / 静默变松

反向测试（把实现改回去，断言必须变红）抓出来的，全都是「测试看着在跑，其实没判别力」：

1. **`grep 'class PlanModeGuard'` 子串匹配**：把类改名 `PlanModeGuardX` 照样命中 →
   断言恒真。改成匹配 `class PlanModeGuard(`。
2. **`grep 'class ConversationBuckets'`**：同上。
3. **`p=$(grep -n ... | cut -d: -f1)` 覆盖了计数器 `p`**：汇总行显示出「84 通过」，
   而实际是 31 条——数字变成了行号。本脚本的计数器叫 `p`/`f`，改用 `pin`/`dwn`。
4. **门禁 5 基线读的是第一个非注释行**（`awk ... {print $1; exit}`），而
   `harness-baseline.txt` 是追加式账本、当前值在**末尾**。于是基线永远停在 142，
   之后每次「往上调一个」都是空写。后果不是红，是**悄悄变松**：新增 5 个 harness、
   其中 5 个改成 SKIP，PASS 仍 ≥142，门禁照过。改取最后一个非注释行。
5. **`\bAudioRecord\b` 会被注释点红**：我写的一句「调用 AudioRecord 会崩」的说明
   就把桌面助手的 G1 断言触发了。改判 `AudioRecord\s*\(`（构造调用）。
   这条是假红不是假绿，但同样有害——守卫第一次因为注释报警，就不会有人再信它。

### 一个必须补的运维动作

`ModelSpec` 的六个 `sha256` 现在都是 `null`。填值流程：

```bash
# 1. 把 latest Release 的资产下到本地
# 2. 生成并核对
scripts/tools/model-hashes.sh ~/Downloads/release-assets
# 3. 把输出的 sha256 粘进 ModelSpec 对应条目
```

**注意顺序**：`tts-zipvoice.zip` 现在多带两个许可文件，每次重新打包都会变哈希。
先打包、再算哈希、最后填常量。反了就会让用户看到「哈希与内置值不一致」——
那条文案本身没错，但会让人以为是攻击。
