# 技能声明的可见性（W-55）

> 上一轮把「技能脚本只能发往声明过的域名」做成了**实现**，这一轮补上**告知**。

**基线**：`2ccdf3a`（main）
**对应审计遗留项**：声明了 `net_hosts`，但安装页与技能中心一处都没展示

## 一、问题：判定成立，授权没成立

上一轮加的判据是干净的：manifest 写 `net_hosts`，脚本桥第三道门按它放行，跨域一律拒。
但它有一个前提没被满足——**用户从没看过那串域名**。

`net_hosts` 只存在于 zip 里的 `skill.json`。用户在安装页看到的是「名称 + 描述 + 版本」，
在技能中心看到的是「脚本/提示词 · 是否授权 · 能力上限 + 工具白名单」。点「安装」那一刻，
包已经下载完、解压完、落了盘。

于是整个链条是：

```
用户点「安装」 → 包落地 → 用户点「授权脚本」 → 脚本可以访问 api.example.com
                                                ↑ 这一步的同意范围，他从没见过
```

`SkillNetGrant` 的注释写着「事先授权的载体就是 manifest 的 `net_hosts`，展示在安装页」——
那句话在当时是**承诺**，不是事实。这一轮把它变成事实。

同类问题的第二个面：市场索引里有个 `permissions` 字段（`["network"]`），
它是市场方的**营销文案**，远端可控。用它代替 `net_hosts` 展示，
等于让分发方替技能作者声明它要连哪里。所以确认框读的是**包内原文**。

## 二、做法

### 2.1 三个字段的翻译：`SkillDeclarations.of`

输入特意不是 `SkillManifest`，而是三个原始字段（`netHosts` / `entry` / `tools`）：
那个类是 `@Serializable` 且与 `SkillExecutor` 同包，直接依赖会把 `android.content.Context`
拖进 harness 的编译面（`SkillProtocol.kt` 引了它），纯 JVM 编不过。
判据留在纯函数里，Android 依赖留给接线层——与 `SkillNetGrant`、`MarketRules` 同一套路。

产出：

| 字段 | 内容 | 为什么单独存在 |
|---|---|---|
| `hosts` | 规范化 + 去重后的可用域名 | 展示口径必须与 `HostAllowlist.matches` 一致（它也是先 normalize 再比） |
| `invalidHosts` | 写法非法、运行时会被忽略的条目（原文） | 静默丢弃等于让作者永远找不到「为什么联网总失败」 |
| `needsScript` | `entry` 非空 | 与「能不能执行脚本」（由 trust 决定）是两件事，混在一起就是第二个真相源 |

`hosts` 与 `invalidHosts` 的分界用的是**同一个函数** `HostAllowlist.validateEntry`——
不是另写一份「看起来像域名」的正则。两处各写一份，必然漂移成「UI 说是合法、运行时说不命中」。

### 2.2 四种文案，互不顶替

```kotlin
!needsScript                -> "提示词型 · 不执行脚本"
hosts 空 && invalid 空       -> "未声明域名 · 脚本无法联网"
hosts 空 && invalid 非空     -> "域名声明全部非法 · 脚本无法联网"
否则                         -> "可联网：a.com、b.com、c.com 等 N 个"
```

每一句都对应一个会让用户误解的坑：

- 提示词型技能写「可联网」——它根本不会联网，那句话只是让人白担心；
- 没声明时写「不联网」——真实情况是**连不上**，不是不想连；
- 「全非法」与「没声明」合并——作者明明写了东西，UI 却说「什么都没写」，他只会去检查字段名拼写。

第三条尤其重要：`"*"` 是作者最常写的「我要访问网络」。它被判非法之后，
技能每次联网都被拒，而运行时错误只说「不在声明范围内」。装机前的这一行是唯一能纠正它的地方。

### 2.3 安装确认：下载完**不落盘**

`MarketFacade.installMarketPlugin` 拆成两段：

```
下载 → 校验 id → 解析包内 manifest → 挂到 marketPending（不落盘）
                                        ↓ 用户点「安装」
                                     installZip
```

包体留在 facade 的私有字段（`pendingBytes`），不放 `MarketInstallPreview`：
那是 data class，`equals` 对 `ByteArray` 是引用比较，等于每次状态重放都白持有一份 8MB 引用。

确认后**不重新下载**：重新下载会引入一次 TOCTOU——用户确认的是「他看过声明的那一份」，
再取一次可能已经不是同一份。

关框 = 取消（`cancelMarketInstall`），包体立即释放。这是必须的：
若关框只清 UI 不清 pending，用户下次点安装会**跳过确认直接装**。

### 2.4 技能中心：常驻一行 + 授权框逐条列

- 卡片上常驻「可联网：……」——授权之后还得能查「它当初要连哪里」；
  有非法项时整行转成 error 色。
- 「授权脚本」的确认框里逐条列出域名。**授权正是 `net_hosts` 生效的那一刻**：
  在此之前，那些域名对用户只是 zip 里的一串字符。

「声明」与「工具清单」在卡片上并排展示，读法是一对：

> 声明 = 它**说**自己要做什么（manifest 原话）
> 工具清单 = 它**实际**能做成什么（能力门放行结果）

只有前者，用户不知道它真能干成什么；只有后者，用户不知道它想干什么。

### 2.5 顺带收紧：带端口的主机名也算写错

`net_hosts` 里写 `api.example.com:443`（作者意图大概是「只允许 443」）时，
`matchesOne` 比的是剥掉端口后的 host，这条声明**永远不命中**——与写错 `*` 是同一种静默失效。
所以 `HostAllowlist.validateEntry` 现在对含冒号、且不以 `[` 开头的条目直接判非法
（`[::1]` 这类 IPv6 字面量保留：冒号是地址的一部分）。

## 三、不变量（写进 harness，改坏就红）

1. **UI 列出的域名 ⟺ 运行时放行的域名**：`hosts` 里每一条都能过 `validateEntry`，
   且 `HostAllowlist.matches(hosts, url)` 的判定面与展示集合一致（E1）。
2. **非法项不进 `hosts`**：展示为空 ⇒ 判定为不放行（E2）。这条把「UI 说连不上」和
   「实际连不上」钉在一起，避免出现「提示说不能连、实际能连」。
3. **互斥文案**：「没声明」与「声明全非法」不能同时出现（D4）。

### 关于那个 3588

`SkillUiInfo` 需要多一个 `declaration` 字段，而它是纯数据、不碰任何 VM 状态。
把它和 `SkillToolInfo` 一起搬到 `ui/SkillUi.kt`（同包，引用点一行没改）后，
`ChatViewModel` 净减 9 行，冻结上限跟着往下调到 3588。

这也正好回应 `arch-baseline.txt` 里那句话：「能靠拆文件不抬的，就别抬」——
这次不仅没抬，还往回挪了一格。

## 五、代价与没做的

**代价**

- 市场安装从「一次点击」变成「两次点击」。这是有意的：一次点击的版本里，
  用户同意的东西和他看到的东西不是同一个。
- 包体在确认期间驻留内存（上限 8MB，`MarketRules.MAX_PACKAGE_BYTES`）。可接受。

**没做的**

1. **本地 zip 导入（SAF 选文件 / URL）仍是一次点击落盘**。那条路径与市场共用
   `installZip`，但没有插确认框——`ChatViewModel` 的行数是冻结的，插进去要 +30 行以上。
   缓解：导入后技能卡立即显示声明行，且脚本默认禁止（要联网必须再走一次授权确认，
   那里已经列域名了）。真正修它需要把导入编排从 VM 里抽出来，是一次独立改动。
2. **市场索引的 `permissions` 仍是营销文案**，现在只是不再冒充授权依据。
   彻底的做法是安装后以 manifest 为准回写 UI（已是现状），索引那条字段可以废弃。
3. `net_hosts` 之外的能力（`tools` 里声明了 `shell_run` 之类）目前只展示不拦截——
   能力门已经会按 trust 收紧，展示出来是为了让人看见「它还想干什么」。
