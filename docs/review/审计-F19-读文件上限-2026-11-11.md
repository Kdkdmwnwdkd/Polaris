# 审计 F19：`read_file` 的 limit 只管返回、不管读取（2026-11-11）

## 结论

`read_file` 的分页参数此前只限制**返回给模型的那一段**，文件仍被整份读进堆：
工作区里放一个大文件，`limit` 还没生效，进程先 OOM。同一次改动还暴露出第二个问题——
按码元切页会把 emoji 劈成两半，两页各自都是非法文本。

## 缺陷（修前）

```kotlin
val full = file.readText()                     // ← 整份载入堆
val end = (offset + limit).coerceAtMost(full.length)
val snippet = full.substring(offset, end)      // ← 再切出一页
```

工具描述写的是「避免一次性把大文件灌爆上下文」——对上下文成立，对**堆**不成立。

对照实验（同一份 36MB 文件、同一个 `-Xmx64m`）：

```
旧路径  file.readText()               → THROWN OutOfMemoryError: Java heap space
新路径  TextFileSlice.read(limit=32)  → 返回 32 字符
```

同一个家族的错误本项目修过两次（`BackupArchive` 的 zip 炸弹、`ShizukuShell` 的
`copyToCapped`），结论一致：**上限必须在读的过程中生效，不能在读完之后的切片里生效**。

第二个问题：`String.length` 数的是 UTF-16 码元，一个 emoji 占 2 个。`substring` 落在代理对
中间时，第一页以孤立高位代理结尾、第二页以孤立低位代理开头——序列化成 JSON 会变成 `?`
或被上游拒绝，拼回去也不等于原文。

## 修法

- `core/.../TextFileSlice.kt`（零 Android 依赖，只用 `java.io`）：
  - 边读边拼，内存只与 `limit` 有关；
  - 页尾探一个码元，是低位代理就并进来（本页可能多 1 个码元），返回 `nextOffset` 供续读；
  - `offset` 手工传到代理对中间时，丢掉那半个码点，不产出以孤立低位代理开头的页；
  - `limit` 硬顶 65536，工具侧不再自己 coerce（上限单点）。
- `ReadFileTool` 委托 `TextFileSlice.read`，不再 `readText()`；
- 提示文案如实：本次字符数 + 文件字节数 + `offset=${slice.nextOffset}`，
  不再声称「文件共 N 字符」（那要整份扫一遍才数得准）。

**工具描述与参数文案一字未动**：默认工具面预算本来就顶在 525/525，多写一句就要从别处砍
token。第一次提交正是踩在这里——`run-tool-surface-verification.sh` 当场报
`550 token ≤ 525（超 25）`。修法是把描述改回原文，而不是抬预算。

## 验证

`scripts/qa/run-text-file-slice-verification.sh`：11 条行为断言 + 5 条接线断言，16/16 通过。

| 断言 | 守的是什么 |
|---|---|
| A1/A2 | 小文件整读；超长文件只返回一页 |
| A3 | 逐页读到底，拼接结果逐字符等于原文（含中文 / emoji / CRLF） |
| A4/A5 | 页尾不劈代理对；用 `nextOffset` 续读不重不漏 |
| A6 | 手工把 offset 传到代理对中间，不产出非法页 |
| A7/A10 | offset 越界、空文件 |
| A8/A9 | limit 硬顶；limit ≤ 0 当 1 |
| B1 | 36MB 文件在 `-Xmx64m` 下读 32 字符（旧实现在此必 OOM） |
| W1~W5 | 不再整份载入 / 走分页实现 / 续读用 `nextOffset` / 单点定义 / 上限单点 |

变异 5 次，全部变红（退出码 1）：页尾不并入低位代理、`hasMore` 恒 false、
`nextOffset` 手算、去掉起点对齐、`limit` 不生效。

`assertion-census.py` 文本断言 1729 条不变；`harness-baseline.txt` 136 → 137。

## 遗留

- `edit_file` 仍整份 `readText()`：它必须看到全文才能做唯一性校验，属于另一个问题
  （要改成流式匹配 + 原子替换），本轮未动；
- `http_request` 的 `resp.body.string()` 同样无上限：响应体先整份进内存再截到 8000 字符，
  与 F19 同因不同点，待单独处理。
