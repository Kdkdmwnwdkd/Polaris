## 一、为什么是"移植"而不是 merge

远端有 17 个分支，13 个已并入 main。剩下三个 `runtime/*` 分支是同一串提交的叠加：

```

ea20716 W-RT2 资源分档
e89412a W-RT3 审批档位
ea85f03 W-RT4 提示词变量
1583a93 W-RT5 SSH 远端 shell
9374cbe W-RT6 知识库检索
bab5462 W-RT7 费用下钻
fa31b35 W-RT8 二维码导入导出
229968b W-RT9 长对话归档
```

不能 `git merge`：那批提交的包名还是 `com.example.agentkit`、`core/` 还在 app 模块里，
`terminal/` 与 `ConversationStore` 在此期间都重构过（R-10 分片、W-55 候选回落、
W-56/57 身份语义）。硬合的冲突面比逐块重做还大，而且会把"哪一行是功能、哪一行是解冲突"
搅在一起，事后没法审。

所以按 W-RT1 的先例逐块移植：**规则层一字不改**（档位表、正则、BM25 权重、价格表、
二维码编码算法），只改接线与包名，每块配一个能真跑的 harness。

## 三、每块的裁决点

### W-RT2 资源分档：档位是**上限**，不是**设定值**

`ResourcePlan.effectiveThreads` / `capContext` 都是 `minOf`：用户填 16 线程、性能档给 8，
结果就是 8。理由写在文件头——档位来自机型画像（内存/核数），它只会**压低**用户设置，
不会替用户往高里调；"我设了 16 却跑 8"必须是可解释的，所以设置页那四选一就在推理参数
组的**最前面**，选完下面两个数值框会跟着显示被压到多少。

`resolve(lock, advice)` 里 `locked ?: advice?.let(::autoTier) ?: return unprobed()`——
画像缺失时 AUTO **不猜档**（这条是旧分支 CI 抓出来的雷，`322d11b`/`db5157e` 两次修）。

### W-RT3 审批档位：`requestApproval` 传的是**归组键**，不是 `grant.key`

原先的会话内放行按 `grant.key` 判，而 `grant.key` 是"这一次调用的具体键"（比如某条命令），
归组键才是"这一类"（`GROUP_FILE_WRITE` 等）。档位判定必须按类：AUTO 档放行的是一整类
安全操作，不是某一串字符串。旧分支这里传错过，`b30f01c` 的提交信息里写了为什么不能
"优化回去"。

STRICT 档额外绕过了"截图本回合已批准"的缓存——那条缓存是为 STANDARD 设计的减噪机制，
在逐条确认档下复用等于偷偷削掉一层确认。

### W-RT4 提示词变量：正则与填槽语义原样搬

`{{ name }}` 抽取、`distinct()` 保序、未提供的变量原样保留（不填空串）——这三条都是
行为断言钉住的。UI 侧只多了一个填槽弹窗与选择器里的分流（有变量才弹）。

### W-RT5 SSH：三条硬约束在第九节之外还有两条实现细节

1. **不引入 SSH 协议库**：直接跑 `ssh` 命令行，把进程包成 `ProcessBackendBase` 的子类。
   `BatchMode=yes` 是安全边界（密码交互会卡死无 PTY 会话），档案里干脆没有密码字段。
2. **降级链排除**（详见审查指南第七节第 9 点）：`KEY_SSH` 进 `known` 名单、不进任何 `order`。

### W-RT6 知识库：`memory` 组，不新开分组

`knowledge_search` 登记进 `ToolCatalog` 的 `memory` 组（组描述改成"跨会话记忆与本地资料
的读写检索"）。新开一个组会让工具面板多一行只有一个工具的组——分组是给模型做选择用的，
不是分类学。`KernelExposureVerification` 的工具名清单 56 → 57。

### W-RT7 费用下钻：本地推理统一记 `local-llama`

价格表里 `local-llama` 是 0，且不会因本地模型文件名含 "gpt-4" 被云端价格表误命中。
误算比不显示更糟——所以 `priceFor` 对陌生模型如实返回 `null`，UI 显示"价格未知，未计入合计"，
合计在有未知项时也返回 `null` 而不是"装作 0"。

### W-RT8 二维码：381 行的编码器**没有**被改写

`QrCode.kt` 是自写的 QR 编码器（零依赖）。这条最值得审——所以验证方式不是"看代码"，
而是**拿 zxing 真解码器对拍**：6 组负载（含 v8/v9、v10 边界、M 档贴上限）、往返、
5 条拒收（非本格式 / 坏编码 / 重度截断 / 空关键字段 / 旧前缀）。CI 里由
`Prefetch zxing` 步骤取考官包，取不到就 SKIP 并明确打印"编码器未被外部解码器验证"。

前缀 `agentkit://config` 改成了 `beichen://config`：App 已改名，此功能从未发布，
没有历史码需要兼容。

### W-RT9 归档：一段代码里有两个"看起来对"的坑

- **JSONL 必须一行一轮**：旧分支用 `prettyPrint = true` 的 `json` 往 `.jsonl` 写，
  一轮摊成几十行；读的时候 `readLines()` 逐行解析全部失败、坏行被 `runCatching` 安静跳过。
  写进去了，永远读不回来——比不归档更糟（用户以为历史还在，导出却是空的）。
  现在归档专用 `archiveJson`（紧凑），读写同一个实例。
- **清理放 `persist` 不放 `delete()`**：归档文件与分片是同级的旁路文件，删除会话时
  一起清；但清理必须发生在落盘线程（`batch.removed` 循环），`delete()` 只改内存 + 排任务。
  功能相同、纪律不同——主线程不碰磁盘。

## 四、与本仓既有演化冲突、必须改写的六处

旧分支的代码不能照抄，因为它写的时候本仓还没有这些东西：

| 冲突 | 本仓的既有事实 | 改写方式 |
|---|---|---|
| 包名 | `:core` 已独立成模块 | 全部 `com.beichen.polaris`，terminal/knowledge/qr 落 `:core` |
| 归档删除 | `delete()` 走 `removedIds` + `persist` | 清理进 `persist` 的 removed 循环 |
| schema 生成 | `TerminalIdentity.schemaValues()` 由 `usable` 过滤 | `Ssh.usable = true`，否则模型看不到 ssh |
| 降级链 | `providersFor` 会把未登记的 provider **追加**进链尾（D4 变异测试逼出来的） | `KEY_SSH` 进 `known`，只经 `obtainByKey` |
| 身份语义 | `satisfies`：会话实际身份须满足本次下限 | `pool.run` 对 ssh 传 `null`；`SshBackend` 声明 `User` |
| 行数纪律 | `arch-baseline` 只减不增 | 二维码拆出 `QrConfigSection.kt`（+31 而非 +144） |

## 六、没做到的（如实列）

1. **Android / Compose 层没有编译过**。沙箱无 Android SDK，`SshChannelSection.kt`、
   `ModelConfigScreen` 的档位单选组、`PermissionsScreen` 的接线都只有静态断言与
   人工比对。这是本轮最大的未知数——CI 第一轮大概率会在这几处报错。
2. **没有推送、没有 CI 记录**。沙箱无 GitHub 凭据（`git push` 报 `could not read Username`）。
   所以第八节表格里"编译 / APK"两行是 ⏳，不是 ✅。
3. **真机没验**：SSH 真连远端、本地模型三档的实际 tok/s、审批跳框的手感、
   二维码在真实屏幕亮度下的识别率。
4. **文本断言的计数口径有个洞**：`assertion-census.py` 只认 `expect` / `fixed` / `refute`
   三个函数名，本轮 8 个 harness 的静态断言用的是 `has` / `hasnt`，于是**没被计入 census**
   （总数仍是 1368 / 53 文件）。这不是刻意绕过——命名沿用了旧分支的 `has`——但口径上确实
   放走了 132 条新文本断言。要不要把它们统一改成 `expect` 并抬基线，留给下一轮裁决。
